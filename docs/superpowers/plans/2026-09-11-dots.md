# DOTS implementation plan

> Execute the approved design with test-driven development and independent code review.

**Goal:** Record dated SBD totals, calculate DOTS, and give four normalized components equal weight in Ihmisarvo.

**Architecture:** PostgreSQL stores raw lifts and a bodyweight snapshot. Profile sex selects DOTS coefficients. Frontend pure functions calculate DOTS before history aggregation and combine normalized component daily values.

**Tech Stack:** TypeScript, Fastify, PostgreSQL, React/RTK Query, Playwright.

## Tasks

- [x] Backend: add migration `0013_sbd_measurement.sql`, nullable `users.sex`
  (`male`/`female`), and SBD owner CRUD in `backend/src/race/sbd.ts`.
  Payload is `{ measuredAt, squatKg, benchKg, deadliftKg, bodyweightKg }`;
  responses add `id`. Dates are UTC, valid and not future; lift bounds
  0.1–1000 and bodyweight 1–500, precision 0.1. Reject missing profile sex.
  Profile PUT accepts optional nullable sex for compatibility; omitted sex
  preserves the stored value. GET returns heightCm and sex. Race/radiator
  add sex and sbdMeasurements. Test validation, authorization, ownership,
  persistence, sharing and deletion with `playwright/sbd-api.spec.ts` and
  update `playwright/profile.spec.ts`.
- [x] Pure calculation: test `playwright/dots.spec.ts` first; implement
  `frontend/src/race/dots.ts`, propagate data through `api/raceApi.ts` and
  `race/prepareRace.ts`, add dots mode and history in `race/raceModes.ts`.
  Check known male/female scores, clamping, level boundaries, missing sex,
  and averaging per-reading scores instead of averaged input weights.
- [x] Score: update `race/raceIndices.ts` to require and carry DOTS daily
  history, and return normalized biceps and DOTS component points.
  Formula is `(5*bicepsIndex + bmiIndex + bloodPressureIndex +
  100*dots/novice) / 4`. Update score tests to verify 100 at baseline,
  below/above-Novice results, equal contributions, missing data and dates.
- [x] Settings: update `settings/RaceProfileSettings.tsx` and `api/profileApi.ts`;
  create `settings/SbdSettings.tsx` with separate lift fields, date,
  editable weight prefill from the owner's last reading on/before date,
  preview, validation, list/delete and retry states. Wire `Settings.tsx`.
  Write `playwright/dots-frontend.spec.ts` covering these flows first.
- [x] Dashboard: wire DOTS in `Home.tsx`, sample data, `RaceChart.tsx`,
  `RaceReadings.tsx`, and formatting. Show thresholds for both sexes,
  level labels, points, missing-sex guidance and score explanations.
  Update affected navigation/score browser assertions.
- [x] Verification: run backend tests and both builds; run pure Playwright
  tests, API tests against a disposable migrated database, and targeted
  browser regressions. Inspect desktop/mobile screenshots. Run Biome,
  Markdown lint, Knip and git diff whitespace checks. Independently review
  the complete diff for requirements, correctness and regressions.
- [x] Document usage, new score formula and migration in README; record
  verification results and leave the implementation ready for review.
