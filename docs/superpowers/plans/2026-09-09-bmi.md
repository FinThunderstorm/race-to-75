# BMI implementation plan

**Goal:** Add a BMI comparison view and self-service height settings.

**Architecture:** Keep imported measurements and aggregation in kilograms. Project
prepared readings into a metric-specific view model. Classic uses kg and its
existing goal rules; BMI uses saved height, a 25 reference, and neutral changes.
The authenticated profile API stores nullable height; both race endpoints return it.

**Tech stack:** React, Redux Toolkit Query, TypeScript, Fastify, PostgreSQL, Playwright.

## Work sequence

1. Backend: migration, authenticated GET/PUT `/api/profile`, strict height validation
   (50–300 cm, one decimal), race/radiator height field, API regression coverage.
2. Metric model: optional height on raw/prepared participants; view conversion and
   generic numeric chart bounds; test 81 kg / 1.8² = 25, missing/invalid height,
   neutral BMI badges, values below reference, color stability, and Classic parity.
3. UI: mode selector with URL persistence; BMI chart/table/labels/empty states;
   sample heights; profile form with load/save/retry/clear and cache invalidation.
4. Verify: focused unit/API/browser checks, both application builds, formatting,
   mobile and radiator layouts, independent spec and code review.

Classic remains the default mode; live remains the default source. Missing height
never becomes zero BMI, and missing-height participants remain visible. Entering
height explicitly explains that BMI becomes visible to the group/radiator audience.
BMI is a comparison view, with no lowest-BMI winner. Only BMI is in this release.
